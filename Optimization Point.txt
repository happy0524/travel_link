11/14 장소 호출 횟수 최적화 이후 추가 최적화 

둘 다 맞지만, 주된 원인은 **최적화 부족보다 서비스 구조와 광고 모델의 궁합**이야.

현재 최적화는 이미 상당히 잘 되어 있어. 중복 요청, 전체 Edge 재계산, 검색 결과 전체의 시간대 조회 같은 명백한 낭비는 제거됐다. 하지만 Travel Link는 사용자 한 명이 실제 일정을 만들 때마다 Google의 유료 데이터를 여러 번 소비해야 하는 구조다.

## 광고 수익이 높은 웹사이트와의 차이

| 구분 | 일반 콘텐츠·뉴스·블로그 | Travel Link |
|---|---|---|
| 사용자 행동 | 여러 페이지 열람 | 한 화면에서 일정 편집 |
| 페이지뷰 | 사용자당 여러 회 | 보통 1회 |
| 광고 노출 | 페이지마다 반복 | 한 화면에 제한적 |
| 추가 사용자 비용 | 거의 0원 | 검색·장소·영업시간·경로 비용 발생 |
| 콘텐츠 재사용 | 같은 글을 무제한 제공 | 사용자마다 다른 API 조회 |
| 광고 단가 | 금융·보험·구매 비교는 높음 | 여행 도구는 상황에 따라 다름 |

콘텐츠 웹사이트는 글 하나를 만들어 놓으면 10명에게 보여주든 10만 명에게 보여주든 서버 비용 차이가 작다. 반면 Travel Link는 사용자가 늘 때마다 Google API 호출도 거의 비례해서 증가한다.

즉:

> 일반 웹페이지는 광고수익은 사용자에 비례하지만 비용은 천천히 증가하고, Travel Link는 광고수익과 API 비용이 모두 사용자에 비례한다.

## ‘구글 지도’ 자체보다 비싼 부분

지도 표시 자체는 월 10,000회까지 무료라서 당장 큰 문제가 아니야. 핵심 비용은 다음이다.

1. 장소 검색
2. 영업시간
3. 장소 사진
4. 교통수단별 경로

특히 `regularOpeningHours`는 Place Details Enterprise에 해당해서 월 무료 한도가 1,000회뿐이다. 장소 5개를 확인하면 사용자 약 200명만으로 무료 한도에 도달한다. [developers.google.com](https://developers.google.com/maps/billing-and-pricing/pricing?utm_source=chatgpt.com)

따라서 “Google 지도가 비싸다”기보다는:

> **Google Places의 영업시간처럼 고급 장소 데이터가 광고 기반 무료 서비스에 비해 비싸다.**

라고 보는 게 정확해.

## 아직 남은 최적화도 있다

현재 구현이 비효율적인 것은 아니지만, 비용을 더 낮출 방법은 있어.

### 1. Time Zone API 제거 가능성 검토

Place Details의 `timeZone` 필드를 사용할 수 있다. 이미 영업시간 때문에 Enterprise 등급 Place Details를 요청한다면, 같은 요청에 `timeZone`을 포함해도 가장 높은 SKU는 그대로 Enterprise다.

따라서 장소마다 별도의 Time Zone API를 호출하지 않고:

```text
Place Details 1회
→ 이름
→ 주소
→ 좌표
→ 영업시간
→ IANA 시간대
```

를 함께 받을 수 있는지 현재 JavaScript Places API 구현에서 확인할 가치가 있어.

이렇게 하면 사용자당 Time Zone 요청 4~5회를 없앨 수 있다. 다만 Time Zone 무료 한도가 10,000회이므로 가장 시급한 비용은 아니다.

### 2. 사진 완전 지연 로딩

현재 장소 정보 패널을 열 때 사진을 가져오는데, 다음처럼 바꿀 수 있어.

```text
기본 장소 패널
- 이름
- 주소
- 영업시간
- 사진 보기 버튼

사진 보기 클릭
- 그때만 사진 요청
```

대부분 사용자가 사진을 누르지 않는다면 사진 API 비용을 크게 줄일 수 있다.

### 3. Text Search → Autocomplete

사용자가 장소 이름을 직접 입력해 선택하는 UX라면 Text Search보다 Autocomplete가 적합할 수 있다.

공식 가격표상 한도 초과 후 가격은:

- Text Search Pro: 1,000회당 $32
- Autocomplete Requests: 1,000회당 $2.83

차이가 크다. 다만 세션 토큰과 Place Details를 정확하게 연결하도록 검색 UI를 다시 설계해야 한다. [developers.google.com](https://developers.google.com/maps/billing-and-pricing/pricing?utm_source=chatgpt.com)

### 4. 실시간 교통을 선택 기능으로 전환

자동차 경로에서 `TRAFFIC_AWARE`를 사용하면 Routes Pro가 적용될 수 있다.

- Essentials: 월 10,000회 무료, 이후 $5/1,000회
- Pro: 월 5,000회 무료, 이후 $10/1,000회

여행 날짜가 먼 미래라면 실시간 교통정보의 가치가 낮으므로:

- 기본: 일반 자동차 경로
- 당일 또는 사용자 선택: 실시간 교통 반영

으로 나누는 방법이 있다.

### 5. 영업시간 조회 시점 변경

현재처럼 일정에 추가한 장소만 영업시간을 조회하는 것은 이미 올바른 최적화다.

더 줄이려면:

- 장소를 추가할 때는 이름·주소만 조회
- 사용자가 ‘일정 검토’를 누를 때 영업시간 일괄 확인

방식도 가능하다. 하지만 영업시간 경고가 Travel Link의 핵심 기능이므로, 지나치게 늦추면 사용자 경험이 나빠진다.

## 최적화하면 광고 사업이 될까?

완전히 해결되지는 않아.

사진, 검색, 시간대, Routes를 더 최적화해도 **장소 4~5개의 영업시간을 확인하는 핵심 비용**은 남는다. 이 기능을 유지하는 한 무료 한도 이후 사용자당 일정한 비용이 발생한다.

반면 AdSense는 사용자 국가, 콘텐츠, 광고 배치, 트래픽 등에 따라 수익이 크게 달라지고, Google도 운영 전 정확한 수익을 예측하기 어렵다고 명시한다. [support.google.com](https://support.google.com/adsense/answer/9902?utm_source=chatgpt.com)

Travel Link처럼 한 화면에서 오래 사용하는 도구는 페이지뷰가 적어서 AdSense와 특히 궁합이 좋지 않다.

## 최종 판단

- 현재 코드가 형편없이 비효율적이어서 적자인 것은 아니다.
- Google Places의 영업시간 데이터가 비싸고 무료 한도가 낮은 것이 가장 큰 원인이다.
- SPA 여행 도구라 광고 노출 기회가 적은 것도 큰 원인이다.
- 남은 최적화를 적용하면 비용을 상당히 낮출 수 있지만, 광고만으로 안정적인 흑자 구조를 만들기는 여전히 어렵다.

그래서 Travel Link에는 일반 배너 광고보다 다음이 더 잘 맞는다.

- 호텔·숙소 예약 제휴
- 입장권·투어 예약 제휴
- 교통패스 제휴
- 일정 PDF 내보내기 유료 기능
- 일정 저장·공유·공동편집 프리미엄
- 여행지 스폰서 표시

사용자 한 명이 광고로 몇 원을 만드는 대신, 일부 사용자가 예약 제휴로 수백~수천 원을 만들게 해야 Google API 비용을 감당할 수 있어.
